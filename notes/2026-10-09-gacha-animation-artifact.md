## 中身(HTML から確認できた構成)

- **画面の要素:**
  - 「プリズム召喚」、ピックアップバナー
  - 排出率の表示(SSR 7% / UR 1%)、天井カウンター(「SSR確定まであと20回」)
  - 単発150 / 10連1,500(10連は SR 以上1枠確定)、所持数15,000(デモ用)
  - 演出プレビュー(SSR入り・UR入り10連を試せる)、スキップボタン
- **使っている技術:** 外部ライブラリなしの単一 HTML(約98KB)。
  - 粒子・光: Canvas + `requestAnimationFrame`
  - 動き: CSS アニメーション約20種(slam / stampIn / shake / sheen / hueSpin / urBlink など)
  - 効果音: Web Audio API でオシレーターとノイズから合成(音声ファイルなし)
  - 振動: `navigator.vibrate`
- **演出の組み立て(ここが学べるポイント):**
  - **段階的な昇格:** 光の色が「青 → 金 → 虹 → UR」と段階的に上がる。結果のレア度ごとに、どの段階を通るかを確率で選ぶ。
    - 例: SSR は「いきなり虹」45%、「金→虹」40%、「青→金→虹」15%。
  - **ガセ演出:** R でも8%の確率で「金」が光り、青に戻る。期待させてから落とす。
  - **昇格の瞬間:** 効果音の上昇音、フラッシュ、画面の揺れ、振動、リング状の光を同時に出す。
  - **溜め:** 光が中央に集まる・低音が鳴る・上昇音が鳴る、の3つで「溜め」を作ってから開封する。
  - **配慮:** スキップ機能あり。`prefers-reduced-motion`(視差効果を減らす)が有効なら、自動で短縮演出にする。
  - 10連の確定枠の処理と、天井(一定回数で確定)のカウントも実装されている。

## このアプリ(競馬アプリ)での活かし方

- 課金ガチャを作るのではなく、**演出の文法**を借りる。例:
  - **予想・結果の発表演出:** 「本命発表」「レース確定」で、溜め → 段階的な色の変化 → 開封、の流れを使う。
  - **お気に入り馬の勝利通知:** 色の段階で「入着 / 勝利 / 重賞勝利」を表す。
  - **連続ログインやバッジ獲得:** スタンプが押される(stampIn / slam)演出。
- 一言の依頼でもここまで作れる。たたき台は Claude に作らせ、SwiftUI に移植する。
  - Canvas の粒子は `TimelineView` + `Canvas`、揺れは `.offset` + spring、振動は `UIImpactFeedbackGenerator` / `.sensoryFeedback` に置き換えられる。
- 文字のカットイン素材は、文字画像APNGメーカー(過去メモ)と組み合わせることもできる。

## 注意点

- **アプリに有料ガチャ(ランダムな有料アイテム)を入れる場合:**
  - App Store ガイドライン 3.1.1 で、**購入前に排出確率を表示する義務**がある。
  - 日本ではコンプガチャが景品表示法で禁止されている。業界団体のガイドライン(確率表示・上限など)もある。
- **ガセ演出の扱い:** 遊びの演出なら問題ない。ただし、競馬の予想・オッズ・的中に関わる表示では、誤解を招く演出(当たりそうに見せる)は使わない。ギャンブルをあおる表現になり、審査・信頼の両面でリスクがある。
- **Reduce Motion とスキップは必須にする。** この Artifact の実装を見習う。
