## 投稿で挙がっていたサイト

| サイト | 種類 | 使いどころ |
| --- | --- | --- |
| [UI Pocket](https://ui-pocket.com) | 国内スマホアプリのUI事例集(と思われる。この環境からは中身未確認) | 日本のアプリの画面・文言を見る |
| [Mobbin](https://mobbin.com) | 実在アプリのスクショ・画面遷移の大規模ライブラリ(iOS / Android / Web) | 「オンボーディング」「課金画面」「設定」など、画面の種類別に実例を比べる。一部有料 |
| [Refero](https://refero.design) | 実在プロダクトの画面ライブラリ(Web中心、モバイルもあり) | 要素(表・フィルタ・空状態など)単位で探す |
| [Page Flows](https://pageflows.com) | 操作の流れを動画・連続画面で記録 | 登録・購入・解約など「流れ」を確認する |
| [Dribbble](https://dribbble.com) | デザイナーの作品投稿SNS | 見た目のアイデア・雰囲気を探す。※ 実装されていない「見せる用」も多いので、使いやすさの参考にはしすぎない |
| [Material Design](https://material.io) | Google のデザインシステム(Android 標準) | 色の体系・余白・状態表示などの原則を学ぶ |
| [Apple Design(HIG)](https://developer.apple.com/design/) | Apple のヒューマンインターフェイスガイドライン、テンプレート、SF Symbols | **iOS アプリでは最優先**。審査にも関わる |

- 投稿者は「ガイドラインをむっちゃ読んでいた」とのこと。事例集で目を養い、ガイドラインで理由を理解する、の両輪が大事。

## 使い分けの考え方

1. **まずガイドライン(HIG)で基本を押さえる。**
   - ナビゲーション、タップ領域44pt、Dynamic Type、ダークモード、SF Symbols。
2. **実在アプリの事例で「普通はどう作るか」を確認する。** Mobbin / Refero / Page Flows / UI Pocket を使う。
3. **Dribbble で見た目の味付けを探す。** 最後に、少しだけ取り入れる。

## このアプリ(競馬アプリ)での活かし方

- **画面ごとに実例を集める:**
  - 出馬表のような**密度の高い表**: スポーツ・株・金融アプリの一覧画面が参考になる。
  - **フィルタ・並び替え**、**お気に入り登録**、**通知設定**、**オンボーディング**、**ATT の事前説明画面**も集める。
- **AI に渡す:**
  - 集めたスクショ数枚と DESIGN.md(DESIGN.md のメモ参照)を Claude に渡し、「この構成で、DESIGN.md の色と文字で SwiftUI を書いて」と頼む。
  - 「AIっぽいUI」を避ける一番の近道になる。
- **国内の競馬アプリの比較:** 文言・情報の並べ方・広告の入れ方を比べ、自分のアプリの差別化ポイントを決める。
- **流れの確認:** Page Flows で、課金・解約・初回起動の流れを確認する。App Store の審査で問題になりやすい部分(課金の説明・解約方法の分かりやすさ)の参考にする。

## 注意点

- 事例サイトのスクショは、各アプリの著作物。自分用の参考にとどめ、ストア画像・資料へそのまま転載しない。
- 他社アプリの見た目を丸ごと真似ると、模倣としてリジェクトされうる(App Store ガイドライン 4.1)。
- Material は Android 向け。iOS アプリにそのまま当てはめず、原則だけ取り入れる。例: 戻るボタンの位置やタブバーは、iOS の慣習(HIG)に従う。
