# App Store の新クリエイティブアセット(ヘッダー画像・検索結果ビジュアル)

- 出典: X(Twitter)の投稿(#aso。ユーザーが本文を共有。投稿URLは未記録)
- 保存日: 2026-10-09
- タグ: #ASO #AppStoreConnect #ストア画像 #CVR

## 投稿の内容

- App Store Connect から、プロダクトページ上部に**大きなヘッダー画像**(5244×2950px)を設定できるようになった。
- **検索結果の見た目**もカスタマイズできるようになった。CTR(タップ率)と CVR(インストール率)を上げるASOのチャンス。

## 確認できたこと(2026-10-09時点。主に第三者の解説記事・開発者のGitHubから)

- **iOS 27 / iPadOS 27 以降**で表示される。表示場所は、プロダクトページ、検索結果、フィーチャー掲載時。
  - 古いOSでは今まで通りスクリーンショットが表示される。
- **設定しない場合の検索結果の表示**(フォールバック):
  1. 検索用アセットがあればそれ
  2. なければ、アプリを持っている人には In-App Event
  3. 次に App Preview(動画)
  4. 最後に先頭のスクリーンショット
  - つまり既存アプリでも、何もしなければ従来のスクショ表示が続く。
- **サイズ**(報告ベース。要公式確認):

| 種類 | 比率 | サイズ | 備考 |
| --- | --- | --- | --- |
| ユニバーサル | 16:9 | 5244×2950 | PNG。ヘッダーと検索結果の両方に使える |
| ヘッダー専用 | 21:9 | 3840×1646 | 5〜30秒の動画も可 |
| 検索結果専用 | 3:2 | 1920×1280〜3840×2560 | 5〜30秒の動画も可 |

- 新しい **Asset Library** で管理する。アセットだけ審査に出せて、**アプリのアップデートは不要**。承認済みのアセットは再審査なしで使い回せる。
- **カスタムプロダクトページ(CPP)と組み合わせられる。プロダクトページの最適化(PPO)でA/Bテストもできる。**
- Appleの公式発表は 2026-10-05 ごろとされる。ただしこちらで公式ページは直接確認できていない。書き出し前に App Store Connect の画面と Apple のテンプレートで仕様を確認する。

## 既存アプリもやるべきか(判断メモ)

- **結論: やる価値は高い。** 理由:
  - アップデート不要・独立審査なので、手間とリスクが小さい。
  - 初期は設定済みのアプリが少ないので、検索結果で目立ちやすい(先行者メリット)。
  - 失敗しても PPO の結果を見て戻せばよい。
- 優先順位の目安:
  1. **検索経由のインストールが多いアプリ**(App Analytics の「App Store 検索」の割合で確認) → 最優先
  2. 指名検索(アプリ名で検索)が中心のアプリ → 効果は小さめ。後回しでもよい
- 進め方:
  1. まず**ユニバーサル(5244×2950)を1枚**作り、ヘッダーと検索結果の両方に使う。
  2. PPO で「新アセットあり / なし(従来のスクショ)」を比べる。2〜4週間で CVR を比較する。
  3. 効果があれば、検索用の専用比率(3:2)や動画を追加する。キーワード別に CPP も作る。

## このアプリ(競馬アプリ)での注意

- 「必ず当たる」「儲かる」と受け取れる表現は避ける。ガイドライン違反(誤解を招く表現)やリジェクトのリスクがある。年齢レーティングとも整合させる。
- JRA などの公式ロゴ、馬・騎手の実写写真、他社の商標は使用許諾がないかぎり使わない。
- 文字は大きく、少なめに。検索結果では縮小表示されるので、スマホで実寸確認する。
- 作成の流れ(過去メモを参照):
  1. Compositor で `.comp` を AI に作らせる
  2. PNG で書き出す
  3. `asc` で登録する。※ 新アセットへの対応状況は `asc` 側で要確認

## 追記: キーワード別の出し分け(2件目の投稿より、2026-10-09)

- **CPP をキーワードに割り当てると、検索キーワードごとに表示を切り替えられる。** 切り替わるのはスクショと Creative Asset(画像/動画)。
- Creative Asset は Asset Library から単体で審査できる。承認済みなら、**公開中のアプリでも新しいバイナリなしで差し替えできる**。
- 意味: 検索意図ごとに「検索結果 → プロダクトページ」まで一貫したクリエイティブを見せられる。

### 競馬アプリでのキーワード別CPP案(たたき台)

| 検索意図 | キーワード例 | 見せる内容 |
| --- | --- | --- |
| 予想・データを見たい | 競馬 予想 / 競馬 データ | 予想・分析画面、データの見やすさ |
| レース情報を追いたい | 出馬表 / レース結果 / オッズ | 出馬表・結果画面の速さ・見やすさ |
| 重賞・G1を楽しみたい | G1 / 有馬記念 / 日本ダービー(時期限定) | 開催直前に差し替える特集ビジュアル |
| 初心者 | 競馬 初心者 / 馬券 買い方 | わかりやすさ・用語解説 |

- 進め方:
  1. App Store Connect の検索キーワード(App Analytics)で、インストールにつながっている語を確認する。
  2. 上位3〜4の検索意図だけ CPP を作る。作りすぎると管理が大変。
  3. 各 CPP の CVR をデフォルトページと比べ、勝ったものだけ残す。
- G1 などの時期ものは、バイナリ不要で差し替えられる利点が特に大きい。開催の約1週間前に審査に出す。
- 注意:
  - 他社の商標や「有馬記念」などのレース名は、キーワード割り当て・画像内の表記の可否を審査ガイドラインで確認する。
  - 「当たる」系の表現は避ける。
  - CPP をキーワードに割り当てられる条件・上限は、App Store Connect で要確認(投稿ベースの情報)。
