## 投稿の内容

- 日本全国の施設データ 約337万件。内訳は Overture Maps 249万件 + 食品営業許可データ 88万件。
- **APIキー不要・無料・商用利用可**。
- 検索結果を DB に保存してOK。
- MCP 対応。
- **利用時は出典表示が必要**。
- 検索ボックスを簡単に追加できる SDK も公開を検討中。

## 確認状況(2026-10-09)

- この環境からは docs.openpoiapi.com に接続できず、公式ドキュメントは未確認。

  - 商用利用・保存は可。

- 使う前に公式で確認すること:
  - エンドポイント・パラメータ
  - レート制限
  - 出典表示の正確な文言
  - 保存時に残す必要があるフィールド
  - MCP の設定方法

## このアプリ(競馬アプリ)での活かし方

- **競馬場・WINS(場外馬券発売所)・周辺施設の検索。** 例: 「近くのWINS」「競馬場周辺の飲食店」を表示する。
  - 競馬場・WINS そのものは数が少ない(全国数十か所)。自前のマスタデータを持つほうが確実。
  - 使いどころは周辺の飲食店・駐車場・駅など。食品営業許可データ88万件が強み。
- **開発中の調査に MCP を使う。** Claude Code から施設データを直接検索し、テストデータやマスタ作成の下調べをする。
- 検索結果を DB に保存できる。よく使う施設はアプリ側でキャッシュし、API への負荷と依存を減らせる。

## 注意点

- **出典表示は必須。** アプリ内に表示場所を用意する(例: 設定 > ライセンス / 施設詳細画面の下部)。
- **プライバシーポリシーの更新が必要になる。** ユーザーの現在地を API に送る場合:
  - このリポジトリの `index.html` は「3. 外部サービスへの提供」に記載のサービス以外には提供しない、という内容になっている。
  - OpenPOI API を「3.」に追記し、位置情報の取得目的も明記する。
  - iOS の位置情報の許可文言(`NSLocationWhenInUseUsageDescription`)と、App Store のプライバシー表示(「位置情報」)も合わせて更新する。
- 無料・キー不要のサービスは、終了や仕様変更のリスクがある。
  - 取得部分は差し替えやすく作る。リポジトリ層などで抽象化する。
  - 障害時は保存済みデータで表示を続けられるようにする。
- 食品営業許可データは「許可」の記録であり、営業中かどうか・閉店済みかどうかは保証されない。
