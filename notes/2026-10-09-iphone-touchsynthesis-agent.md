## 投稿の主張

- iPhone上で完結するエージェントが、Macを繋がずにiPhoneのあらゆる操作(タップ・文字入力)を行える。いわゆる「iPhone版 Computer Use」。

## 実際の仕組み(README・コードから確認)

- iPhoneの画面タッチ自動化と画面ストリーミングを行うアプリ。Mac不要、脱獄不要、WebDriverAgent不要。
- アプリ自身が「IDE役(testmanagerd とDTX通信)」と「XCTestランナー役」を1プロセスで兼ねる **self-runner** 方式。
- 内部では **XCTestのプライベートAPI**(`XCSynthesizedEventRecord`, `XCPointerEventPath`)でタップ・スワイプ・ピンチ・文字入力・ハードボタン操作を合成する。
- スクショは JPEG で約15〜25FPS。
- **ローカルネットワーク上のTCP(ポート8347、長さ付きJSON)** で外部クライアントから操作する。
  - コマンド: `tap` / `swipe` / `typeText` / `pressButton` / `screenshot` / `startStream` など。
  - 「AI」はアプリ自体には入っていない。AIエージェント側がこのTCP APIを叩いて操作する構成。
- 前提条件:
  - iOS 26以上(iPhone 13 Pro / iOS 26.3 で検証)
  - LocalDevVPN などでのDDIマウントとVPNループバック
  - **信頼済みMacのペアリングレコード**(初回だけMacが必要)
  - XcodeGen + Xcode 16 + Rust でのビルド
- 起動時に約60秒のセットアップがある。パスコード入力後、画面に「Automation Running」が表示される。

## このアプリ(競馬アプリ)での活かし方

- **実機でのE2Eテスト・動作確認をAIに任せる**。例: 主要画面を巡回してスクショを撮り、崩れをチェックする。
- **ストア用スクリーンショットの撮影を自動化**。撮影した画像を、前のメモ(App Store Connect API + `asc`)の流れでそのまま登録できる。
- ATT許可ダイアログなど、審査用の操作録画の再現手順を自動化する(このリポジトリの `att_confirmation.mp4` のようなもの)。
- ※ 個人開発の手元の検証環境用と考える。

## 注意点・リスク

- **App Storeで配布できるものではない。** XCTestのプライベートAPIやDTXプロトコルを使っているので、開発・検証用ツールとして扱う。自分のアプリに組み込むと審査リジェクトになる。
- **TCPサーバーに認証がない**(コード上、認証・トークンの処理は見当たらなかった)。同じネットワークにいる人なら誰でも端末を操作したり画面を見たりできる可能性がある。自宅など信頼できるネットワーク以外では起動しない。使い終わったらすぐ停止する。
- ペアリングレコードは端末を完全に信頼させる情報なので、厳重に扱う。
- **LICENSEファイルが見当たらない**(2026-10-09時点)。コードの流用や改変には権利上の注意が必要。
- iOSのバージョンアップで動かなくなる可能性が高い(非公開APIに依存しているため)。
- 停止しても画面のオーバーレイが残る場合は、音量ボタンを長押しする(README記載)。
