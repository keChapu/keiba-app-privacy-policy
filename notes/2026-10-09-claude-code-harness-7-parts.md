## 要点

- 長い仕事で起きる3つの問題は、AI の頭が悪いからではなく、「職場(ハーネス)」がないから起きる。
  - 途中で止まる
  - 翌日に忘れている
  - もっともらしい間違いが混ざる
- AI が賢くなるのを待つより、AI が働く環境を整えたほうが早い。一度作れば、テーマと資料を入れ替えるだけで使い回せる。

## 準備:フォルダを3つ作る

- `sources/`(資料棚)、`drafts/`(作業机)、`published/`(金庫)。

## 7つの仕掛け

| # | 仕掛け | 職場のたとえ | Claude Code での実体 | ポイント |
| --- | --- | --- | --- | --- |
| 1 | 共通ルール | 就業規則 | `CLAUDE.md`(`/memory` で確認) | いつでも通用するルールだけを書く。「1回だけの好み」は規則にしない |
| 2 | 繰り返す手順 | 業務マニュアル | `.claude/skills/<名前>/SKILL.md`(`/名前 テーマ` で呼ぶ。`$ARGUMENTS` に入力が入る) | **各手順に「目に見える結果」を決める**(例: 確認表を drafts/checks.md に保存) |
| 3 | 外部資料への接続 | 資料室の鍵 | MCP(`claude mcp add ...`、`/mcp` で確認) | 鍵を渡しすぎない。読むだけなら書き込み権限は渡さない。使わない接続は止める |
| 4 | 触ってはいけない場所 | 立入禁止の札 | `.claude/settings.json` の `permissions.deny`(例: `Read(.env)`、`Edit(published/**)`。`/permissions` で確認) | 効くのは標準のファイル操作だけ。スクリプト経由までは完全には防げない。バックアップは別に取る |
| 5 | 事実確認 | 校閲担当 | `.claude/agents/evidence-reviewer.md`(読む・調べる道具だけを持つサブエージェント) | **一番のおすすめ。** 書き手とは別の AI に、一次情報と照らして「正しい / 誤り / 未確認」の表で返させる |
| 6 | 考える深さ | 担当ごとの本気度 | effort(書き手は medium、校閲担当はファイルで high) | 「よく考えて」と書いても設定は変わらない。設定を変える |
| 7 | 完了の条件 | 納品の条件 | `/goal`(条件を満たすまで続ける。判定は別の AI) | 条件は「ファイルが保存され、保存先と結果が会話に表示されている」のように**見て確かめられる形**にする |

### 校閲担当のポイント

- 判定は「正しい / 誤り / 未確認」の3つ。**未確認なら、足りない証拠を書かせる。**
- 「確認しました」という報告ではなく、**保存されたファイルを開いて確かめる**。公開されるのは会話ではなくファイル。
- 1か所を直したら、前後の文も読み直す。

### 引き継ぎメモ `progress.md`

- 書く項目: 仕事 / 成果物の保存先 / 終わったこと / 決めたこと(根拠) / 残った課題 / 次にやること。
- 翌日は「progress.md を読んで、『次にやること』から続けて、終わったら更新して」と頼むだけ。
- AI が最初からやり直そうとしたら、メモに情報が足りないサイン。

### 効果の測り方

- `/usage` の利用量(確認役・やり直しの分も含める)、自分の確認時間、手直しの量、完了条件を満たせたか。
- 設定は1つずつ変えて、同じ仕事で比べる。

### 始め方

- まずは **1(CLAUDE.md)と 5(校閲担当)** の2つから。
- 慣れたら 2(スキル)、7(完了条件)、引き継ぎメモ。
- MCP と権限は、必要になってから足す。

### 最新トピック:Mods(2026-10-02 発表と記事にある)

- Claude Code の動作や画面を、数行の TypeScript で改造できる。プラグインとして `/plugin` で入れる。Claude に作らせることもできる。
- 例: 会話の埋まり具合を天気予報のように表示する。標準の「You should know」は、見落としやすい情報を知らせる。
- **Mods は Claude Code と同じ権限でパソコンにアクセスする。** 信頼できる配布元のものだけ使う。

## 確認状況

- CLAUDE.md / Skills(`$ARGUMENTS`)/ サブエージェント / `permissions.deny` / MCP / `/memory` `/agents` `/permissions` `/context` `/rewind` `/usage` は、Claude Code の既存機能として整合している。
- `/goal`、サブエージェントの `effort:` 指定、`--effort` オプション、Mods の詳細(`cc-plugin-you-should-know@builtin` など)は、記事の記載どおりに記録したもの。この環境からは公式ドキュメントで確認していない。使う前に `/help` や公式ドキュメントで確認する。

## このアプリ(競馬アプリ)開発での活かし方

ハーネスの型を、アプリ開発用に置き換える。

- **CLAUDE.md(共通ルール):**
  - ビルド・テストのコマンド
  - 「完了前に `xcodebuild test` と lint を通す」
  - 「課金・ATT・個人情報まわりは人がレビューする」
  - 「UI は DESIGN.md に従う」
- **スキルの例:**
  - `/release-notes`: 差分からリリースノートを下書き → 【要確認】を付ける → 保存。
  - `/store-assets`: スクショ → Compositor で加工 → `asc` で登録。**提出だけは人がやる。**
  - `/privacy-check`: アプリで使っている外部サービス・権限を一覧にし、このリポジトリの `index.html` と差分を表で出す。
- **校閲担当(サブエージェント):**
  - 「プライバシーポリシー・ストアの説明文・リリースノートの記述を、実際のコードと照らして確認する」役。
  - 「正しい / 誤り / 未確認」の表で返させる。
  - 審査リジェクトやポリシーと実装のずれを防げる。
- **権限:**
  - `.env` や API キー、App Store Connect の `.p8` キーを `deny` にする。
  - 公開中のポリシー(main ブランチ)の直接編集は避け、作業ブランチで直す。
- **引き継ぎメモ:** 長い作業(ストア画像の更新など)は `progress.md` で翌日に引き継ぐ。
