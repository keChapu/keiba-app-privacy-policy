# UIの微調整は「調整用のスライダーUI」をAIに作らせる

- 出典: X(Twitter)の投稿(@usutaku_channel。動画とスクショをユーザーが共有)
  - https://x.com/usutaku_channel/status/2092850729757327753
- 保存日: 2026-10-09
- タグ: #UI #プロンプト #ワークフロー #Codex #ClaudeCode

## 投稿の内容

- Codex に UI の修正を言葉で指示しても、微調整がうまく伝わらなかった。
- そこで「**自分で調整するための UI**」を作ってもらった。手で直感的に整えたあと、その値を本体に反映してもらったら楽だった。
- スクショの例(Slack 風のリアクションボタンの調整):
  - スライダー: 左右余白 8px / 上下余白 0px / 丸み 12px / 絵文字 14px / 高さ 27px。
  - 「調整後」と「現在」を並べてプレビューする。
  - 「この値で反映する」ボタンで、AI に値を渡す。
  - AI 側の返答: 「下のスライダーで直感的に調整し、『この値で反映する』を押してください。その数値を本体へ反映して本番で出します」。

## なぜ効くか

- 「もう少し小さく」「ちょっと丸く」のような言葉は、AI と人で解釈がずれる。何往復もかかる。
- 数値を人が手で決めれば、AI は「その数値を反映する」だけになり、ずれが起きない。
- 決めた値はそのままデザイントークン(DESIGN.md)に書き戻せる。

## 頼み方の例

```text
このボタンの見た目を調整したいです。
左右余白・上下余白・角丸・文字サイズ・高さをスライダーで変えられる
調整用のプレビュー画面を作ってください。
変更前と変更後を並べて表示し、決まった数値を一覧で出せるようにしてください。
私が値を決めたら、その数値で本体のコードを修正してください。
```

## このアプリ(競馬アプリ)での活かし方

- **SwiftUI なら Xcode プレビューで同じことができる。**
  - `#Preview` の中で `@Previewable @State` と `Slider` を使い、余白・角丸・フォントサイズを動かす調整用プレビューを Claude に作らせる。
  - アプリ本体には入れずに済む。
- **実機で確かめたい値は、デバッグビルド限定の調整パネルにする**(`#if DEBUG`)。例:
  - 出馬表の行の高さ、オッズの文字サイズ、枠番の色の濃さ。
  - 演出のタイミング(ガチャ演出のメモの「溜め」の長さなど)。
- Web ページ(このリポジトリの `index.html` / `support.html`)なら、Claude にスライダー付きの HTML を作らせて同じように調整できる。
- 決まった値は DESIGN.md のトークンに書き戻す。以後の画面にも同じ値を使う(DESIGN.md のメモ参照)。

## 注意点

- 調整用のコードを本番ビルドに残さない。`#if DEBUG` か、プレビュー専用にする。
- 1画面だけで値を決めると全体の統一が崩れる。共通のトークンを変えるのか、その部品だけ変えるのかを決めてから反映させる。
