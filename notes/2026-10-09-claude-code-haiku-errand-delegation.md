## 投稿の主張

- 上位モデル(Fable / Opus)のまま簡単な作業までさせると、トークンを無駄にする。モデルの戻し忘れも起きる。
- Anthropic が Haiku 4.5 の発表時に示した形を再現する:
  - 「**賢いモデルが問題を計画に分解し、複数の Haiku を指揮してサブタスクを並列で片づける**」
- 効果は2つ:
  1. 品質差の出ない作業を安い単価で処理できる。
  2. **(本命)下請けが読んだ中身は、指揮役の会話に残らない。** 指揮役が自分で大量に読むと、その中身が以降の往復すべてに乗り続ける。長い作業ほど効く。
- 例: 原稿2本を突き合わせて特定の表現を拾う作業 → Haiku に回し、約30秒・約25,000トークンで結果だけ返ってきた。
- 投稿に書かれた Haiku の性能:
  - 実務的なコーディングのベンチマーク 73.3%
  - 速度は上位モデルの最大4〜5倍
  - 価格は最上位の10分の1
- ※ 単価の比較は投稿内でも「5倍」と「10分の1」が混在している。現在の料金は公式の料金表で確認する。

## 配布プロンプトの設計(要約)

### 準備(安全策)

- `node --version` を確認する。動かなければ止めて相談する。
- スクリプトはすべて Node.js で書く。日本語の文字化けを防ぎ、Windows / macOS / Linux 共通で動かすため。
- `~/.claude/settings.json` と `~/.claude/CLAUDE.md` を、**日時付きの名前**でバックアップする(2回目の実行で最初のバックアップを上書きしないため)。
- settings.json は手で書き直さない。Node で読み込んで項目を足し、書き戻す。
  - hooks は配列に1件追加するだけにして、既存のフックを残す。すでに登録済みなら追加しない。
- コマンドやパスは `~` ではなく絶対パスで書く。

### ① 下請けサブエージェント `~/.claude/agents/errand.md`

- frontmatter に `model: haiku` を指定する。ツールは **Read / Glob / Grep の読み取り専用**。
- 任せる作業: 探す・読む・数える・拾い出す・指定の形式に整えて返す。書き込みは本体が行う。
- 任せない作業: 設計・企画・判断・文章づくり・実装。判断が必要になったら止めて報告させる。
- `description` には、どんなときに呼ぶべきかを具体的に書く(本体が呼ぶかどうかの判断材料になる)。
- `~/.claude/CLAUDE.md` に「## モデルの役割分担」を追記する:
  - 機械的な作業は errand に委譲し、何をなぜ委譲するかを1行で宣言する。
  - 判断・設計・文章づくり・実装は自分で行う。
  - errand の結果は、採用前に妥当性を確認する。
  - **迷ったら委譲しない**(既定は自分で処理する)。

### ② 番犬フック `~/.claude/hooks/model-guard.js`(UserPromptSubmit)

- 標準入力の JSON から `transcript_path` と `prompt` を取り出す。
- transcript(JSONL)を末尾から遡り、`type: "assistant"` の `message.model` から現在のモデル名を得る。
- **ずれがあるときだけ**、`{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"..."}}` を出力する。
  - Haiku で重い依頼(実装・設計・執筆など) → 「モデルを上げることを提案して」と伝える。
  - Opus / Fable で機械的な依頼だけ(重い語が混ざっていない) → 「errand への委譲を検討して」と伝える。
- **ブロックしない。** 終了コード2や `decision:"block"` は使わない(誤検知で入力が消えるのを防ぐ)。該当しなければ何も出さずに終了コード0で終わる。
- 判定結果はログに1行ずつ追記する。ログの書き込みに失敗してもフックは止めない。
- 最後に、合成した transcript で動作確認する。変更ファイルの一覧と、元に戻す手順を報告させる。

## 評価・補足

- 設計はよくできている。特に次の3点:
  - 読み取り専用で任せる範囲を絞る
  - 迷ったら委譲しない
  - フックはブロックせず助言だけ
- `additionalContext` を `hookSpecificOutput` の中に入れる、という点は Claude Code のフック仕様どおり。
- Claude Code には標準でも調査用のサブエージェントがあり、軽いモデルで動くものもある。自作の errand と役割が重ならないよう、description で使い分けを明確にする。
- 番犬の判定はキーワード照合なので取りこぼしがある。投稿者も「完全な自動化ではない」と書いている。

## このアプリ(競馬アプリ)開発での活かし方

- アプリ本体の開発では、errand に向く作業が多い:
  - 「この画面の文言を全部拾う」「`NSLocalizedString` の未翻訳キーを数える」「プライバシーに関わる API 呼び出しの箇所を一覧にする」
  - App Store 用の文言をリポジトリから集める
- **プライバシーポリシー(このリポジトリ)との突き合わせ**も向いている。errand に「アプリで使っている外部サービス・権限の一覧」を作らせ、本体が `index.html` の記載と差分を判断する。
- 導入は**手元の Mac の Claude Code** で行う(`~/.claude` はユーザー単位の設定)。今のクラウドセッションのコンテナは一時的なので、ここで設定しても残らない。

## 注意点

- 設定を変える前のバックアップと、元に戻す手順の確認を必ず行う(プロンプトにも含まれている)。
- フックは送信のたびに実行される。重い処理を入れない。
